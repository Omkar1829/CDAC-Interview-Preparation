📚 rt.jar / Standard Modules
🗃️ java.util & Collections
🔌 java.io & java.nio
⚙️ JVM (Java Virtual Machine)

Virtual engine executing bytecode. Converts platform-neutral bytecode into OS-native machine instructions.

📥 1. ClassLoader Subsystem
  • Loading: Bootstrap, Extension/Platform, Application loaders.
  • Linking: Verify bytecode, Prepare static fields, Resolve references.
  • Initialization: Execute static initializers & static blocks.
🧠 2. JVM Memory Areas
  • Method Area / Metaspace: Class data, static variables, method metadata.
  • Heap Memory: All object instances (`new Object()`) & instance fields.
  • JVM Stack: Local variables, frame stacks, method return addresses.
  • PC Register: Current executing instruction address per thread.
  • Native Stack: C/C++ native method execution frames.
⚡ 3. Execution Engine & JIT
  • Interpreter: Reads & executes bytecode line-by-line (Fast start, slow loop).
  • JIT Compiler (Just-In-Time): Compiles "Hotspot" loops into native machine code.
  • Profiler: Detects frequently called methods ("hot spots").
  • Garbage Collector (GC): Reclaims memory of unreachable heap objects automatically.

JDK Deep Dive
JDK (Java Development Kit)

The JDK is a complete software development environment used to develop Java applications.

  • Formula: JDK = JRE + Development Tools
  • Includes tools like javac (compiler), jdb (debugger), jar (archiver), and javap (disassembler).
  • Target User: Software developers writing and compiling code.
  • Platform Dependent: You must download JDK specific to Windows, macOS, or Linux.
JRE Deep Dive
JRE (Java Runtime Environment)

The JRE is the implementation software that allows a compiled Java program to run.

  • Formula: JRE = JVM + Core Class Libraries
  • Contains standard runtime libraries (like rt.jar / Java modules) required for program execution.
  • Does NOT contain development tools like javac compiler.
  • Target User: End users running Java desktop or server applications.
JVM Deep Dive
JVM (Java Virtual Machine)

The JVM is an abstract virtual machine that executes Java bytecode.

  • Platform Independence: Write Once, Run Anywhere (WORA) works because Java code compiles to bytecode, which any platform-specific JVM can execute.
  • Key Components:
    • ClassLoader Subsystem: Loads, links, and initializes `.class` files.
    • Runtime Data Areas: Method Area (Metaspace), Heap, JVM Stack, PC Register, Native Method Stack.
    • Execution Engine: Interpreter, JIT Compiler, Garbage Collector.
JIT Compiler Deep Dive
JIT (Just-In-Time) Compiler

The JIT Compiler is a component of the JVM Execution Engine designed to dramatically improve execution speed.

  • Why JIT? Pure interpretation line-by-line is slow. JIT identifies "Hot Spots" (frequently executed methods/loops) and compiles those bytecode sections directly into native machine code once.
  • Caching: The compiled native code is cached in code memory so subsequent calls run at native speed without re-interpreting.
  • Adaptive Optimization: JIT performs inline expansion, dead code elimination, and loop unrolling dynamically at runtime.
Q1: What is the main difference between JDK, JRE, and JVM? ▼
JDK is the full development toolkit (Compiler + Tools + JRE).
JRE is the runtime environment required to execute Java apps (JVM + Libraries).
JVM is the virtual execution engine that converts bytecode into native machine instructions.
Q2: Why is Java called platform independent while JVM is platform dependent? ▼
Java code compiles to neutral bytecode (.class files), which is identical across all operating systems. However, each operating system needs a specialized JVM written specifically for its native architecture (Windows JVM vs Linux JVM vs macOS JVM) to translate bytecode into that OS's specific machine code.
Q3: How does JIT Compiler improve Java performance compared to pure interpretation? ▼
The interpreter converts bytecode to machine code line-by-line, which adds overhead during loops. The JIT Compiler identifies frequently executed code blocks ("hot spots") and compiles those bytecode blocks into native machine code directly. It caches this native code so future executions bypass the interpreter completely, matching C/C++ execution speeds.
Q4: Where are static variables and object instances stored in JVM memory? ▼
* Static variables & class metadata: Stored in Metaspace / Method Area.
* All Object instances (created with new): Stored in Heap Memory.
* Primitive local variables & object reference variables: Stored in the thread's JVM Stack.
Q5: What happens when you type java Main in terminal? ▼
1. OS starts a new JVM process.
2. ClassLoader loads Main.class into Metaspace and links it.
3. JVM locates public static void main(String[] args).
4. Main thread stack frame is created on JVM Stack.
5. Execution Engine interprets bytecode & JIT compiles hotspots to native execution.
